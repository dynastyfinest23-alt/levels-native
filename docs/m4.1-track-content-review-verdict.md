## Findings by criterion group

**1. Raw zone/enum tokens — no findings, one judgment note.** No zone token (`builder`, `love_flow`, ...) appears anywhere. Track enum token names (`under_3mo`, `strange_foreign`, `true_open`, ...) never surface in copy. The one deliberate call: the cross-exam title "Fact or conclusion" uses the same two English words as the `belief_verdict` wire values (`fact` / `conclusion`). I judge this a pass, same reasoning as M3.2's "preparation mode" call: these are ordinary words carrying the question's actual diagnostic content — the enum was evidently named after the concept, not the other way around — and neither word exposes any scoring or zone mechanic. Nothing about the token *mapping* becomes visible; the user sees a plain dichotomy. Pass.

**2. Zone names as identity nouns — no findings.** None of the six zone display concepts (collapsed, contracted, reactive, threshold, builder, flow) appear as words at all, in any grammatical role. "Something moved or loosened" and "It got stronger, more present" describe body sensation, not zones. Pass.

**3. Book/calibration vocabulary — no findings.** None of the Dodson anchor words (shame, apathy, grief, fear, desire, anger, pride, contentment, courage, willingness, neutrality, love) appears, nor any scale/level/calibration language. This file has zero lexical overlap with the anchor set — cleaner than the drill file on this axis. The file's own header claim that book canon does not gate this content is consistent with what I found: no book numbers or classifications anywhere. Pass.

**4. Mechanic numbers / instrument meta-commentary — no findings; reasoning follows since numbers do appear.** The numbers present are all calendar durations about the *user's own life and protocol cadence*: "A few months, tops", "One to three years", "a year from now", "Compared to day one", "this week", "A few days ago". None is a score, floor, ceiling, loop count, or measurement claim, and none narrates the scoring instrument. "Compared to day one, does this feel any different in your body?" asks about the user's felt state across days the user knowingly lived through — that is the protocol's visible structure, not instrument meta-commentary. The integrity check ("is this still sitting here a year from now, the same way?") interrogates the user's project, not the app's measurement of it. Pass.

**5. Bridge question as invitation — N/A.** No bridge question is authored in this file. The nearest analogue — the 72h check-in prompt "A few days ago you committed to something specific. Did it happen?" — references the user's prior answer only to anchor the question, then asks something genuinely new (did it happen), so no data-panel recap occurs. Pass where applicable.

**6. Manufactured urgency — no findings; reasoning follows since this file contains the sharpest line in the app so far.** The completion integrity check is deliberately confrontational: "If nothing about your approach changes, is this still sitting here a year from now, the same way?" I score this pass, on three grounds: (a) it is about the user's stalled project, not their energy state — the rubric's urgency clause targets alarm framing around energy state; (b) it manufactures nothing — it points at a timeline the user just reported themselves (it only fires after a duration/statement mismatch); (c) it explicitly de-escalates in the next sentence: "you don't have to act on it yet." Similarly, "A commitment with no real constraint rarely survives a normal week" is a plain observation used to justify the next question, not a countdown or a threat. The embodiment daily loop has no streak-guilt mechanics in copy — day 6 and day 7 are addressed as structure, never as "don't break the chain." Pass.

**7. Permanent identity / single-assessment Flow — no findings; reasoning follows since the identity statements were the priority check.**

The seven daily identity statements are, by design, first-person identity claims the user *tries on* — which is exactly the territory criterion 7 polices. The line I applied (same as M3.2): identity content is allowed when it is the user's own voice about their own experience, and disallowed when the app's voice asserts or implies permanence — with one addition specific to this mechanic: a statement offered as a *hypothesis to test* is not an app-voice assertion, provided the instrument genuinely lets the user reject it.

That proviso holds here. Every daily statement is immediately followed by the body-response check, whose three options include "Strange, like it belongs to someone else" and "False — like I'm lying to myself." The app hands the user a sentence and then asks, without prejudice, whether it was a lie. That is the structural opposite of the app declaring who the user is. Applying it statement by statement:

- "This reaction is old. I am not." (day 3) — dis-identifies the person from the pattern; the exact inverse of permanent-identity framing. **Allowed.**
- "This is loosening its grip, one day at a time." (day 6) — presumes progress that may not have happened, but it is a try-on statement and day 6 also asks the delta question directly, with "No, same as day one" as a first-class answer. The mechanic never forces the user to endorse the progress claim. **Allowed.**
- "This isn't running me anymore — I am." (day 7) — the strongest claim in the set; same hypothesis-to-test structure, same false-option escape hatch. **Allowed.**
- "I've done the harder thing before. I can do it again." (day 5) — the only statement asserting an unverifiable biographical fact rather than a present-tense stance. Noted below (finding D) but non-blocking: the false/strange options cover the user for whom it does not land.

On the low-zone side: nothing in the file labels the user with their pattern ("this pattern", "this reaction", "this belief" are consistently framed as things the user *has* or *runs*, never things the user *is*). No copy implies Flow, mentions reachability, or promises any destination. Pass.

**8. Variable reward framing — no findings.** Nothing implies any result is randomized, negotiable, or inflated. Largely N/A to static track copy. Pass.

**9. AI-tell vocabulary / puffery — no findings.** No `delete-ai-words` violations (no unlock/elevate/journey/seamless/empower/dive-in/game-changer), no inflated claims. Two example lists were checked against the rule-of-three clause: "tight, hot, heavy, hollow" (four items, and they are functional scaffolding for a sensation-naming task, not rhetorical rhythm) and "money, a favor, a forfeit" (three concrete examples of stakes, same category as M3.2's "bosses, parents, rules" — content, not padding). Em-dashes appear singly per string, never chained. Pass.

**10. Reframe rhetoric — no findings; reasoning follows.** Two structures needed checking. First, "This isn't running me anymore — I am" is grammatically a "not X — Y" reframe, but it sits inside a user-voice identity statement whose entire function is that contrast, and the user is invited to call it false — the app's narration performs no rhetoric on the user. Second, the file's questions ("Will you actually do it?", "Did it happen?", "What actually got in the way?") are real questions that capture stored answers (`day7_action_confirmed`, `checkin_response`, `checkin_blocker_text`), not rhetorical pivots. All app-voice titles and prompts say the thing directly: "Name it", "Be straight about the timeline", "Say it plainly". Pass.

## Other quality findings (beyond the 10 criteria)

**A. "Actually" tic reintroduced (worth trimming — M3.2 already flagged this as a house tic).** Five occurrences: "has it actually been sitting", "actually verified", "never actually checked", "Will you actually do it?", "What actually got in the way?". Three are load-bearing and should stay ("actually verified" carries the fact/conclusion distinction; "Will you actually do it?" is the confirm gate; "What actually got in the way?" cuts past the rehearsed excuse). Two are redundant: the completion duration prompt already stacks three honesty signals (title "How long, honestly" + "Be straight about the timeline" + "actually"), and the `conclusion` option's "never actually checked" echoes the prompt's own "never checked again" two lines above it. Suggested trims below.

**B. Prompt/option echo in the cross-exam (note only).** The cross-exam prompt ends "...something you concluded once and never checked again?" and the `conclusion` option answers "I decided this was true once and never actually checked" — nearly the same sentence twice on one screen. The fix-A trim reduces this; if Noah wants more distance, "I concluded it once and it's been running unexamined ever since" varies the option without changing its meaning, but I do not consider that required.

**C. Layout coupling in the daily body-response prompt (note only).** "Read the line above once more" hardcodes the identity statement's screen position into copy. If the track screen ever places the statement elsewhere (card, modal, previous screen), the copy silently breaks. "Read the statement once more" costs nothing and decouples it. Relatedly, the stage-4 prompt "You held your attention there for a moment" presumes the screen flow includes an actual attention-hold step before this question — a controller/screen dependency to honor in M4.x UI work, not a copy defect.

**D. Day-5 statement asserts unverifiable biography (note only).** "I've done the harder thing before. I can do it again." is the only identity statement claiming a fact about the user's past rather than offering a present-tense stance. For almost every user it is trivially true, and the strange/false response options cover the rest, so I judge it acceptable — noting it in case Noah prefers all seven statements to stay in the present tense (e.g. "I've handled hard things before. This is one more.").

**E. Duration option overlap (note only, no fix required).** A user two months in can truthfully pick both "A few months, tops" and "Under a year" — the labels describe overlapping ranges rather than exclusive bands. The ascending-list convention resolves it in practice (users pick the first/tightest fit), and the underlying enum bands are exclusive, so no data ambiguity results. If Noah wants belt-and-suspenders, "Somewhere between three months and a year" makes the second band explicit at the cost of stiffer language; I lean toward leaving it.

## Bottom line

This file holds the app-voice/user-voice line correctly in the one place it is genuinely tested — the embodiment identity statements, which read as assertive identity claims but are structurally hypotheses the user is invited to reject, with "False — like I'm lying to myself" as a first-class answer. Every token stays invisible, none of the four mechanic-leak classes appears, and the sharpest line in the file (the completion integrity check) earns its edge by pointing at the user's own reported timeline and then explicitly releasing the pressure. The five notes are polish; finding A (the reintroduced "actually" tic, already flagged in M3.2) is the only one I would actively recommend taking before ship, and the three-row fix table covers it.
