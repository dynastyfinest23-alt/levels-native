# Block Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the optional 48-item block map: answer, score in Postgres, show the wheel, and hand the top domain to the Phase 3 drill as a confirm/override suggestion.

**Architecture:** Two migrations add the config table, two user tables, RLS (no client UPDATE on results), Phase 3 columns, a pure scoring fn and an owner-guarded scoring RPC. The Dart side mirrors the pure fn exactly (mirror-sync group 5), runs a resumable one-item-per-screen runner on the Phase 1 visuals, and renders a `CustomPainter` wheel from the DB row only.

**Tech Stack:** Flutter (web), `go_router`, `supabase_flutter`, plain `ChangeNotifier`; Supabase Postgres via CLI migrations.

**Spec:** `docs/superpowers/specs/2026-11-08-block-map-design.md` (read it with this plan; decisions log: `docs/superpowers/specs/2026-11-08-block-map-brainstorm-notes.md`; review: `docs/superpowers/reviews/2026-11-08-block-map-fable-review.md`).

## Global Constraints

- No new dependencies. State is `ChangeNotifier`. The wheel is a `CustomPainter` (no `fl_chart`).
- The LLM never decides: scoring lives in `compute_block_map`; Dart is an exact integer mirror for preview; UI renders only the DB row.
- No numbers, scores, zone names, or flags on screen. Copy passes the four mechanic-leak classes and delete-ai-words. No em dashes in copy.
- New copy ships only after a cold-context rubric judge pass (M2.4 method).
- Every SECURITY DEFINER fn: `SET search_path = public, pg_temp` + NOT FOUND guard + `auth.uid()` ownership guard. SECURITY INVOKER fns pin `search_path` too. EXECUTE to `authenticated` only.
- No client UPDATE or DELETE right on `block_map_assessments`, ever. Results are written only by `score_block_map`.
- `CREATE POLICY` is always preceded by `DROP POLICY IF EXISTS`. Migrations in `BEGIN/COMMIT`.
- Threshold constants (`straightLineMin` 40, `minimizingMin` 36, `contradictionPairDiff` 3, `contradictionPairsMin` 3) exist in both SQL and Dart and change only together.
- Production migrations run only from `main`, after merge: `git switch main && git pull && npx supabase db push --remote`, then MCP read-back. Never DDL via `execute_sql`.
- One branch + one PR per task (`feat/block-map-<n>-<slug>`). Noah merges. `flutter analyze` clean + `flutter test` green before every commit.
- Routes stay unreachable from the hub (no card) until Task 6.
- Commit messages: imperative, one line, no prefixes, no AI trailers (CLAUDE.md).

## Review Focus

1. **Resume mid-run:** closing at item 20 and reopening continues at the first unanswered key in the stored `item_order`, never reshuffles. Pinned in Task 4.
2. **Create race:** two tabs (or a double open) both create; the second INSERT hits `23505` on `(loop_id, kind)` and must resume the existing session, not show an error. Pinned in Task 4.
3. **Back after finishing:** browser Back from the result route lands on the runner; a completed session must go straight back to the result, never show writable items. Pinned in Task 4.
4. **Rapid double tap:** two taps on one screen write one response row and advance once. Pinned in Task 4.
5. **A lost upsert:** finishing with < 48 stored responses makes `score_block_map` raise; the runner shows the error and jumps to the first missing item. Pinned in Tasks 3 and 4.
6. **Entering early or with no loop:** `/block-map/:loopId` before the loop has a Phase 2 row shows a not-available state and inserts nothing. Pinned in Task 4.
7. **Results tampering / foreign rows:** a client PATCH on `block_map_assessments` is refused; an INSERT against another user's `loop_id` is refused; `score_block_map` on another user's id raises. Pinned in Task 2's read-back and Task 3's levels-verify additions.

## Golden vectors (used by Task 3's Dart mirror test AND its levels-verify SQL)

G8a/G8b `minimizing` at 36 vs 35. The relational `_3` pairing is pinned by Task 2's seed test, not by a vector.
